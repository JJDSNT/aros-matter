# PR #2264 review by Kal (2026-11-15T12:24:11Z)

Source: https://github.com/aros-development-team/AROS/pull/2264 (verbatim)

The new structure is right: one record cache, the `DNSSD` port with requests in a checked envelope, and `dnssd.library` as the only client API. Request validation in `dnssd_ipc_validate()` is thorough. Five unit tests pass on hosted AROS, including the one that changes every byte of a REGISTER (920 refused, no fault). A service registered with `dnssd -R` resolves on AROS with its IPv4 and IPv6 addresses and its TXT. It is announced on the wire with the RFC 6762 TTLs (120 s for the host's address records and the SRV, 4500 s for TXT and PTR). A service announced by another host resolves too, and AROS's own name now resolves from AROS itself. The tools build without a warning, and nothing in the tree uses `bonami.library` any more. The changes below are needed before this goes in.

1. **A session can stop being woken for good (`dnssd/dnssd_api.c:434-437`, `dnssd_server.c:983-988`).** On an empty queue, `mdnsd` keeps the session's notification message (`ss_Notify = msg->dm_Notify`) and replies EMPTY to the READ. If it then queues an event in the same pass of its loop (`dnssdServerTick` -> `push_event` -> `notify()`), it replies the notification message before the client has run. The client then sets `ds_Notify.mn_Node.ln_Type = NT_MESSAGE` over the `NT_REPLYMSG` that `ReplyMsg()` set. From then on `notify_back()` takes it for still lent, the message is never lent again, and the session gets no more signals. `DNSSD_LookupAddressSyncA` then waits until Ctrl-C, and a browse or netmidid hears nothing. Mark the message as lent where mdnsd takes it: in the `Forbid()` at `dnssd_server.c:985`, set `msg->dm_Notify->mn_Node.ln_Type = NT_MESSAGE` before storing it. Then remove lines 435-437 from the library: the client is waiting for the READ's reply while this happens.

2. **The host's own superseded records never leave the cache (`mdns_cache.c:291`).** A cache-flush record ends the other data of its rrset only for remote records (`!local`). A local record with a TTL is always `alive()`, and `make_room()` skips local records. `mdnsRegUpdateRef()` sends goodbyes only for removed addresses. So every TXT or port change of a registration leaves the old local TXT or SRV in the cache beside the new one. A program that updates its TXT now and then grows mdnsd's memory without bound, past `MDNS_CACHE_BYTES`. After the host renames itself, its services' SRVs under the old host name stay too. In `mdnsCacheRecord()`, when `local && flush`, end the other local entries of the same link, name and type with different data: `ce_TTL = 0`, `ce_Expires = now + TICKS`.

3. **Stack overflow in `dnssd_reg_rename()` on 64-bit (`dnssd_reg.c:262-285`).** `number` is an `unsigned long`, parsed from the " (n)" suffix of a name the client chose, and printed into `char digits[12]`. On a 64-bit host it can need 20 digits. Registering "x (10000000000000000000)" and then any conflict, which any host on the link can cause, writes 8 bytes past the array. Parse into a 32-bit counter and take a suffix of more than 9 digits as part of the name.

4. **`DNSSD_CloseSession()` frees memory mdnsd still holds (`dnssd/dnssd_api.c:365-377`).** If the CLOSE message cannot be allocated, or `dnssdSend()` cannot make its reply port, the session is freed anyway, but mdnsd still holds `&session->ds_Notify`. The next event's `ReplyMsg()` then writes into freed memory and links it onto a port. The same happens when CloseSession is called from another task than the one that opened the session, because `find_session()` matches the task. Allocate the CLOSE message and its reply port with the session in `DNSSD_OpenSessionA()`, so closing cannot fail for lack of memory. If CLOSE does not come back DNSSD_OK, keep the session's memory rather than free what mdnsd may still reply to.

5. **Limits chosen by CPU type rather than by available memory (`mdnsd.h:233-239`, `dnssd_server.c:54-61`).** `MDNS_CACHE_BYTES` (24 KB or 128 KB) and `SERVER_OPERATIONS`/`SESSION_OPERATIONS` depend on `__mc68000__`. A 68030 with 64 MB gets the 68000's limits, and an x86 with 32 MB gets the large ones. The event queue is also bounded by count alone (64 per session). One event can be about 9 KB (a QUERY's rdata, a RESOLVED with a large TXT), so 16 slow sessions can pin about 9 MB, filled from the network. Size the cache, the operation budgets and a per-session byte budget for queued events from `AvailMem(MEMF_ANY)` at start-up, as a fraction with a floor and a cap. Treat going over the byte budget like a full queue (drop it, report LOST).

6. **More than 5 KB in one stack frame (`mdns_host.c:383-388`).** `mdnsHostHandleProbe()` has `mine[MDNS_ADDRESS_MAX]` (256 x 20 bytes) plus `other[]` and `fqdn[256]`, under `handle_packet()`'s own locals. The base had `mine[2]`. mdnsd is started without `NP_StackSize`, so on m68k it gets the 16 KB default. Make `mine` static (mdnsd has one task, as other buffers here already assume), or compare straight from the inventory.

7. **netmidid invites 0.0.0.0 (`transport_applemidi.c:866-875`, with `discovery.c:637-652`).** A peer is reported present when it has any address. For one with only an IPv6 address (an IPv6-only host, or one whose AAAA arrived first), `seen->address` is 0, and `applemidi_discovered()` invites it at once at 0.0.0.0. `transport_midi2.c:472-476` already guards this case. Do the same in `applemidi_discovered()`: on `present && !seen->address`, leave `wanted_present` at 0 and return.

8. **netmidid stops reading events after one error (`discovery.c:769-778`).** Any `DNSSD_ReadEvent()` result other than OK, EMPTY, STALE or NOENGINE, for example `DNSSD_ERR_NOMEM` on a small machine, leaves the loop with `reading = 0`. The library lends the notification again only on EMPTY, so nothing ever signals the port again and discovery ends until mdnsd restarts. On those errors keep `reading = 1` and return 0, so that the next periodic turn tries again.

Notes, no change needed in this PR:
- OPEN sets `ss_Active` before `ss_Task`, outside `Forbid()` (`dnssd_server.c:1031-1036`). The TNA_REMOVED hook can see the slot active with the previous owner's task and close the new session. Fill the slot under `Forbid()` when this is next touched.
- `dnssd.h` and `dnssd_api.c` disagree with the code in three places. A name without a dot is said to be taken in "local." (`dnssd_api.c:503`), but only the tool adds it. QueryRecord is said to send ADD/REMOVE, but it sends `DNSSD_EVENT_RECORD` with `DNSSD_EVENTF_REMOVED`. `DNSSD_TXTLength` is said to be at most 1300 (`dnssd.h:147`), but the code allows `DNSSD_TXT_MAX`. Make the comments say what the code does.
- netmidid keys peers per link (`discovery.c:465`), while both transports keep one presence flag per name. A host seen on two links is reported gone when one link goes, though it is still reachable on the other. A full set of 16 peer slots drops ADDs that are never offered again. And peers dropped on LOST or on an mdnsd restart are never reported gone.
- `cache.c:302-305`: a refreshed record keeps its old `ce_Next`, so it is queried early and loses its 80 % query. Set `ce_Next = 0` there.
- A rename that no longer fits 255 bytes leaves `rs_Name` unchanged (`mdns_reg.c:840`). Check `dnssd_reg_service_name()`'s result.
- The tools' largest frames grew to about 1.8 KB (`dnssd.c:581`, `share.c:97`, `sd_common.c:123`). That still fits, but the buffers can be static.
- `mdnsNetIsOwn()` checks only the receiving link's addresses, as before. A host with two interfaces on one segment hears its own announcement on the other one and renames itself.
- One file of the diff ends with an extra blank line (`git apply` warns).
