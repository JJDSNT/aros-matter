# Matter SDK crypto tests on the Linux host, against AROS's mbedTLS

ISSUE-0003, step 3. This runs the SDK's own crypto test (`src/crypto/tests/TestChipCryptoPAL.cpp`) against mbedTLS 3.6.7 built the way AROS builds it, without GN or Pigweed. The goal is to find out what the SDK's mbedTLS backend (`CHIPCryptoPALmbedTLS`) needs from the AROS mbedTLS configuration, before trying it on AROS itself.

## Inputs (kept outside the repo, in `~/aros-local/`)

- `connectedhomeip` at **v1.6.1.0** (`3bcdd56ba5`, the latest stable release, our pin): a sparse clone of `src/`, `config/`, `build/` and `third_party/mbedtls/`, plus the submodules `third_party/nlio/repo`, `third_party/nlassert/repo` and `third_party/googletest` at the commits the SDK pins.
- `mbedtls-3.6.7`: unpacked from the AROS ports cache (`bin/Sources/mbedtls-3.6.7.tar.bz2`).
- `crypto-host/aros-cfg/`: AROS's `mbedtls_aros_config.h` and `mbedtls_platform_aros.c`, unchanged, plus `host-glue/hardware_poll_host.c`, a host `mbedtls_hardware_poll()` built on `getrandom()`.

## What is here

- `build-mbedtls.sh CFGDIR OUT`: builds `library/*.c`, except `net_sockets.c` (as AROS does), with `MBEDTLS_CONFIG_FILE="mbedtls_aros_config.h"`.
- `gen/`: hand-written stand-ins for the headers GN would generate (`core/CHIPBuildConfig.h`, `crypto/CryptoBuildConfig.h` with `chip_crypto = mbedtls`, `system/SystemBuildConfig.h`, …). It also holds:
  - a `pw_unit_test/framework.h` that maps the test to googletest, as the SDK's own googletest mode does;
  - an empty `lib/core/StringBuilderAdapters.h`, since those adapters only pretty-print `CHIP_ERROR` when an assertion fails.

  `asn1/ASN1OID.h` is generated by the SDK's `src/lib/asn1/gen_asn1oid.py`.
- `host-glue/LoggingHost.cpp`: the platform log backend, writing to stderr.
- `srcs.txt`: the SDK sources the test needs.
- `link.sh`: compiles them for one config (`CFG=…`, `LIB=…`), links, and lists the undefined symbols.
- `config-variants/variant-b.diff`, `variant-c.diff`: the options added to the AROS config.
- `flags.template`: the compiler flags.

## Results (2026-10-31)

| Config | Link | `TestChipCryptoPAL` |
|---|---|---|
| A: AROS as shipped | fails: `mbedtls_pkcs5_pbkdf2_hmac` (`MBEDTLS_PKCS5_C`) | not run |
| B: A + `MBEDTLS_PKCS5_C` | ok | 70/71; `TestCSR_GenByKeypair` fails, and the CSR parsing tests only *skip* (`MBEDTLS_X509_CSR_PARSE_C is not enabled`) |
| C: B + `MBEDTLS_X509_CREATE_C`, `MBEDTLS_X509_CSR_PARSE_C`, `MBEDTLS_X509_CSR_WRITE_C` | ok | **71/71** |

In all three, two tests skip because the SDK's mbedTLS backend does not implement `ECDSA_sign_msg_det` and `InitializeFromBitsOrReject` (only OpenSSL/PSA do). The only use outside tests is Network Identity (Wi-Fi network infrastructure), not PASE or CASE.

The PAL needs no patch for 3.6: its `MBEDTLS_VERSION_NUMBER` guards already cover 3.x. The four options add about 16 KB to the library (host, -O1).
